# PostgreSQL Feature Support

This document tracks `pgy`'s support for various PostgreSQL features within its YAML schema definitions and diff engine. It serves both as a capability matrix and a roadmap for future development.

Features are grouped by relative complexity and impact on the diffing engine.

Supported servers: PostgreSQL 15, 16, 17 and 18 (the integration suite runs against each in CI). Syntax specific to a newer release is emitted only when the YAML asks for it: `nullsNotDistinct` needs 15+ (the floor anyway), changing a generated expression needs 17+, and `virtual` generated columns, `enforced: false` and temporal `without overlaps`/`period` keys need 18+.

## Level 1: Basic Schema & Tables
These are the foundational elements required for almost any relational database application.

- [x] **Schemas** (Custom namespaces)
- [x] **Tables** (Base tables)
- [x] **Columns** (Data types, nullability, defaults)
- [x] **Primary Keys** (column `primaryKey: true`, a column list, or a named block that renames a live key and takes `include`, `with` and a `comment`)
- [x] **Foreign Keys** (`onDelete`/`onUpdate`, `match`, `deferrable`/`initiallyDeferred`, `notValid`)
- [x] **Indexes** (`concurrently: true` → `CREATE INDEX CONCURRENTLY` in a no-transaction migration, or for partitioned tables `ON ONLY` + per-partition concurrent builds + `ATTACH PARTITION`; indexes left invalid by an interrupted build are completed or rebuilt; Including unique indexes, non-btree methods via `using:` — gist/gin/brin/hash/spgist and access methods from extensions such as bloom — partial indexes via `where:`, operator classes via `opclass:`/`opclasses:` with their parameters (`gist_trgm_ops(siglen=32)`), expression indexes, per-column sort order — `desc`, `nulls last` —, `include` covering columns, `nullsNotDistinct`, `with` storage parameters, `statisticsTargets` for expression columns (`ALTER INDEX ... ALTER COLUMN n SET STATISTICS`, changed in place) and `concurrently` (built in a separate no-transaction migration). Live definitions are compared in full; a changed index is dropped and recreated under `--unsafe`. Names over 63 bytes are truncated the way PostgreSQL stores them)
- [x] **UNIQUE Constraints** (Table-level and column-level; `nullsNotDistinct`, `deferrable`/`initiallyDeferred`, and `include`/`with` for the constraint's index)
- [x] **CHECK Constraints** (`noInherit`, `notValid`)
- [x] **NOT NULL Constraints** (Via column `nullable` property)
- [x] **EXCLUDE Constraints** (`expression` after `EXCLUDE`, compared with live element by element: a missing `USING`, a named default operator class and `operator(pg_catalog.op)` match what PostgreSQL prints; index storage parameters from the expression's `WITH (...)` or the `with` key, applied at creation and changed in place)
- [x] **Column Alterations** (`ALTER COLUMN ... TYPE / SET DEFAULT / DROP DEFAULT / SET NOT NULL / DROP NOT NULL` for existing columns. Types compared normalized — `varchar(255)` matches live `character varying(255)`, `serial` matches its live `integer` + `nextval` form; defaults compared with live casts stripped (`'x'::text` matches `'x'`). Type changes are gated behind `--unsafe` and support a column-level `using:` expression; around one, the column's default is dropped and set again, redefined or pruned indexes and constraints on the column are dropped first and created afterwards, foreign keys retyped on both sides are dropped and re-added, and generated columns in the way lose their expression or are reported. Guard rails: identity changes follow the identity rules (adding or dropping one needs `--unsafe`), `nextval` defaults are never dropped, primary-key columns never emit `DROP NOT NULL`)
- [x] **Constraint Alterations** (Changed definitions of existing FK/check/unique/exclude constraints emit `DROP CONSTRAINT` + `ADD CONSTRAINT`, gated behind `--unsafe`. Live definitions introspected via `pg_get_constraintdef()`; comparison is normalized — casts, parentheses, whitespace, identifier quoting, and `public.` qualifiers are ignored, so `CHECK ((email <> ''::text))` matches `email <> ''`. FK `onUpdate`/`match`/`deferrable`/`initiallyDeferred`/`notValid`/`enforced`, unique `nullsNotDistinct`/deferrable, check `noInherit`/`notValid`/`enforced`, and PG18 temporal `without overlaps`/`period` columns are modeled and compared; `IN`/`BETWEEN`/`LIKE` rewrites, `CAST(x AS type)` and `pg_catalog.` qualifiers are understood; string literals are compared as written, apart from a `public.` qualifier in one that names an object (`'public.seq'::regclass`). Limitation: primary keys are not compared)
- [x] **Comments** (`COMMENT ON` schemas, tables, columns, indexes, foreign keys, check/unique/exclude constraints, triggers, policies, types, domains, sequences, collations, functions, procedures, views, roles, publications, event triggers; comments of dropped-and-recreated objects are re-applied; diffed against live, PostGraphile smart tags safe)

## Level 2: Advanced Types & Logic
Features that encapsulate business logic, complex data structures, or procedural code.

- [x] **ENUM Types** (Including `ALTER TYPE ... ADD VALUE` for new labels, order-preserving)
- [x] **Composite Types** (Attribute order preserved from YAML declaration; missing attributes added with `ALTER TYPE ... ADD ATTRIBUTE`, type changes/drops under `--unsafe`; attribute `collate` and `comment`)
- [x] **Range Types** (`type: range` with subtype/subtypeOpclass/collation/canonical/subtypeDiff/multirangeTypeName; create-only)
- [x] **Extensions** (`CREATE EXTENSION` with `schema`/`version`/`cascade` and `comment`, created in requirement order from the server's catalog, `dependsOn: [extension <name>]` and the requirements between PostgreSQL's own extensions; relocatable extensions moved with `ALTER EXTENSION ... SET SCHEMA`, with the objects that follow them left alone; version changes emit `ALTER EXTENSION ... UPDATE TO`; both run before anything that uses the extension; `pgy diff` warns about extensions and versions the server cannot install or update to; pulled with non-default versions and requirements; a present `extensions:` block is authoritative for `--unsafe --prune`: installed extensions it does not list are dropped with `DROP EXTENSION` (no `CASCADE`) after every other drop, when they live in a schema the YAML declares objects in; `plpgsql`, the extensions in `.pgy.yml` `prune.keep_extensions`, those a kept extension requires and those still used by objects the plan does not drop are kept, the last with a warning naming the dependents)
- [x] **Objects an extension owns** (a `function` or `procedure` without `body`, a `view` without `query` and a `type` without `type:` manage an existing object and never create it: function attributes via `ALTER FUNCTION`, emitted ahead of the creates that may need them, procedure `security`/`set`, grants, owner and comments; routines matched by argument types; privileges compared with the extension's own (`pg_init_privs`), so its grants stay unless the block names the grantee; applied in the migration that creates the extension; missing objects are reported; `pgy pull` writes the members whose privileges changed, as `pg_dump` does, and reports tables, sequences and aggregates it cannot declare)
- [x] **Functions** (PL/pgSQL, etc.; replace-on-change via body/attribute diff → `CREATE OR REPLACE`; `set` clauses diffed against `proconfig` → `ALTER FUNCTION ... SET / RESET`; `parallel`, `cost` and `rows` diffed → `ALTER FUNCTION`; arg types may be schema-qualified — unqualified and `public.`-qualified are equivalent; overloads with the same name and different arguments are independent declarations)
- [x] **Triggers** (Including `UPDATE OF` columns, `enabled` state (`ENABLE/DISABLE [REPLICA|ALWAYS] TRIGGER`), transition tables via `referencing: {old, new}`, `WHEN (condition)` guards via `when:` and `CREATE CONSTRAINT TRIGGER` with `deferrable`/`initiallyDeferred`. Matched by definition via `pg_get_triggerdef()` — a changed trigger is dropped and recreated in the same migration; equivalent definitions (case, casts, parens, event order, `EXECUTE FUNCTION` vs `PROCEDURE`, a `pg_catalog.` qualifier, and every spelling of an argument: `moddatetime(updated_at)` is `moddatetime('updated_at')`) emit no SQL. Trigger creates are emitted after all table and function creates, so trigger functions may `dependsOn` their own table — needed for SQL-language bodies, which validate at CREATE time. `dependsOn` cycles are a hard error in `pgy diff`)
- [x] **Views** (Standard `CREATE VIEW`; `INSTEAD OF` triggers via `triggers:`; declared queries compared with the live definition through a temporary view (`CREATE OR REPLACE`, or `DROP` and `CREATE` with dependent views under `--unsafe` when columns change); `replace: true` forces `CREATE OR REPLACE` on every diff; `columnComments` → `COMMENT ON COLUMN`; `securityInvoker`/`securityBarrier`/`checkOption` diffed against live reloptions → `ALTER VIEW ... SET/RESET`)
- [x] **Materialized Views** (a changed query recreates the view and its indexes under `--unsafe`; `withData: false`; `with` storage parameters → `ALTER MATERIALIZED VIEW ... SET/RESET (...)`; `indexes:` created and diffed like table indexes)
- [x] **Domains** (`domain <name>:` blocks → `CREATE DOMAIN` with type/collate/default/notNull/check/constraintName and named `checks`; default/not null diffed → `ALTER DOMAIN`, missing checks added, changed checks replaced and undeclared ones dropped under `--unsafe`; comments diffed)
- [x] **Aggregates** (`aggregate <name>(args):` blocks → `CREATE OR REPLACE AGGREGATE` with sfunc/stype/finalfunc/combinefunc/initcond/parallel, the moving-aggregate options, serialfunc/deserialfunc, finalfunc extra/modify, sspace and sortop, ordered-set (`order by` arguments) and hypothetical-set aggregates, created after their functions; diffed against `pg_aggregate`, comments, owners, prunable, pulled)
- [x] **Procedures** (`procedure <name>(args):` blocks → `CREATE PROCEDURE`; replace-on-change via body/security/`set` diff → `CREATE OR REPLACE`; grants, `revokePublic`, comments)
- [x] **Procedural Languages & Transforms** (functions and procedures in any installed language, e.g. PL/Perl, PL/Python, PL/Tcl; `pgy pull` writes each body so the routine is recreated byte for byte, including the first-line indentation PL/Python needs; `body: ""` is an empty body; a changed `language` → `CREATE OR REPLACE`; `transform: [types]` → `TRANSFORM FOR TYPE` for the transform extensions (`hstore_plpython3u`, `jsonb_plperl`, ...), diffed against `protrftypes`, pulled, and kept across `CREATE OR REPLACE` when left unmanaged. Languages and transforms themselves come from extensions; ones created by hand are reported by `pgy pull`)

## Level 3: Architecture & Security
Features necessary for scaling, multi-tenancy, and advanced security models.

- [x] **Table Inheritance** (`inherits: [parents]` → `CREATE TABLE ... INHERITS`, ordered after the parents; missing parents added with `ALTER TABLE ... INHERIT`, removed ones dropped with `NO INHERIT` under `--unsafe`; inherited columns left to the parent, with the child's own settings for them (default, NOT NULL, storage, statistics, comment) under typeless `columns:` entries; pulled)
- [x] **Typed Tables** (`of: schema.type` → `CREATE TABLE ... OF type`, after the type; existing tables linked with `ALTER TABLE ... OF`, unlinked with `NOT OF` under `--unsafe`; column options under typeless `columns:` entries; type attribute changes cascade to typed tables; pulled)
- [x] **Table Partitioning** (Parent `partitionBy: {type: range|list|hash, columns: [...]}`; children as separate tables with `partitionOf` + `forValues` (from/to, in, modulus/remainder) or `default: true` → `CREATE TABLE ... PARTITION OF`; children auto-ordered after parent; a declared partition that is an ordinary table is attached with `ATTACH PARTITION`; bounds are never altered and pgy never detaches; partitions' own column settings under typeless `columns:` entries)
- [x] **Row Level Security (RLS)** (`rowLevelSecurity: true` / `false` + named `policies:` with as (permissive/restrictive)/for/to/using/withCheck; omitting the key leaves live RLS unmanaged, `false` emits `DISABLE ROW LEVEL SECURITY` gated behind `--unsafe`; policies matched by name with definitions diffed — a changed as/for/to/using/withCheck drops and recreates the policy)
- [x] **Grants & Privileges** (`GRANT` / `REVOKE` on tables, views, materialized views, sequences, types, domains, functions, procedures, schemas, foreign servers, and columns — column-level via `grants:` under a column; `PUBLIC` covered by grants blocks on objects with no `PUBLIC` default (tables, views, sequences, columns, servers, schemas), and managed on routines, types and domains when listed (`public: []`) or by `revokePublic`; an empty list (`role: []`) revokes everything for that role while keeping the object managed; all revokes ordered before all grants so narrowing a table grant to column grants is safe)
- [x] **Ownership** (`owner:` on schemas, tables, views, materialized views, sequences, functions, procedures, types, domains → `ALTER ... OWNER TO`, diffed against live)
- [x] **Default Privileges** (top-level `defaultPrivileges:` → `ALTER DEFAULT PRIVILEGES [FOR ROLE] [IN SCHEMA] GRANT/REVOKE` on tables/sequences/functions/types/schemas, with grant option, per-grantee authoritative, emitted before creates)
- [x] **Database Settings** (top-level `database: {set: ...}` → `ALTER DATABASE <current> SET/RESET`, and `database: {roles: ...}` → `ALTER ROLE ... IN DATABASE <current> SET/RESET`, compared with `pg_db_role_setting`, pulled)
- [x] **Roles & Users** (Top-level `roles:` block → `CREATE ROLE` with login/superuser/createdb/createrole/replication/bypassRLS/noinherit/connection limit; `set` → `ALTER ROLE ... SET/RESET`; `inRoles` memberships via `GRANT role TO role`, with admin/inherit/set options, undeclared memberships revoked under `--unsafe --prune` for roles that declare `inRoles`; `validUntil`; explicitly set attributes diffed against `pg_roles` → `ALTER ROLE`; never dropped, no passwords)
- [x] **Sequences** (`sequence <name>:` blocks → `CREATE SEQUENCE IF NOT EXISTS` with as/increment/minValue/maxValue/start/cache/cycle/ownedBy and `unlogged`; set options diffed against `pg_sequence` → `ALTER SEQUENCE`, `unlogged` → `SET LOGGED/UNLOGGED`; comments diffed)
- [x] **Table & Column Storage** (`unlogged` → `SET LOGGED/UNLOGGED` under `--unsafe`; `with` storage parameters → `SET/RESET (...)`; column `collate` (changes under `--unsafe`), `compression`, `storage`, `statisticsTarget` and `nDistinct`/`nDistinctInherited` (attribute options) diffed against live, and applied to added columns in the same migration)
- [x] **Replica Identity** (`replicaIdentity: default|full|nothing|index <name>` → `ALTER TABLE ... REPLICA IDENTITY`, diffed against live)
- [x] **Clustering** (`clusterOn: <index>|none` → `ALTER TABLE ... CLUSTER ON` / `SET WITHOUT CLUSTER`, diffed against `indisclustered`)
- [x] **Extended Statistics** (`statistics:` → `CREATE STATISTICS` with kinds and column/expression lists; drop+recreate on change, `statisticsTarget` → `ALTER STATISTICS ... SET STATISTICS`, comments, prunable)
- [x] **Generated Columns** (Column `generated: <expr>` → `GENERATED ALWAYS AS (expr) STORED`, or `VIRTUAL` with `virtual: true` on PG18+; live generation expressions introspected and compared normalized; under `--unsafe` a changed expression emits `SET EXPRESSION` (PG17+; a warning on 15/16) and a removed one `DROP EXPRESSION`)
- [x] **NOT NULL NOT VALID** (PostgreSQL 18: a column with `notValid: true` keeps its not-null constraint `NOT VALID`; pulled from `convalidated = false` not-null constraints)
- [x] **Identity Columns** (Column `identity: always | byDefault`, or a map with sequence options (start/increment/minValue/maxValue/cache/cycle, and `sequenceName`, renamed in place) → `GENERATED ... AS IDENTITY (...)`; kind and options diffed → `SET GENERATED` / `SET <option>`; added to or dropped from existing columns under `--unsafe`; overrides `default`)

## Migration Workflow
How pgy plans, reviews and applies changes safely.

- [x] **Adopting a database** (`pgy pull` writes YAML that diffs clean against the source database and rebuilds it from scratch; `--data` includes table rows)
- [x] **Search-path independent comparison** (the database is read with `search_path` pinned to `public`, so `pgy diff` gives the same plan and `pgy pull` the same YAML through every connection, whatever the role, database or DSN sets; the schema of anything in `public` or on the connection's `search_path` is optional in the YAML, `pgy pull` qualifies everything outside `public`, and a changed `database.set.search_path` is also set for the session that runs the migration)
- [x] **Offline validation** (`pgy validate`: JSON Schema, unknown columns, unresolvable dependencies, cycles, invalid combinations; `pgy diff` repeats its errors as warnings)
- [x] **Split migrations** (`diff --split` writes one migration per schema file or directory, ordered by dependencies, with cross-file references deferred to the group that can satisfy them)
- [x] **Transaction-free migrations** (`-- pgy:no-transaction`; generated for `concurrently: true` indexes, including the `ON ONLY` + per-partition + `ATTACH` sequence on partitioned tables; interrupted builds are completed or rebuilt)
- [x] **Lock retries** (`migrate --lock-timeout D --retries N [--retry-wait D]` rolls back and retries a transactional migration that hit `lock_timeout` or a deadlock, with doubling waits up to 30s)
- [x] **Two-step constraint validation** (foreign keys and checks added to existing tables are added `NOT VALID` and validated in the no-transaction migration, retried by `pgy diff` until they succeed; `notValid: true` leaves them unvalidated, and dropping it emits `VALIDATE CONSTRAINT`; NOT VALID foreign keys on partitioned tables before PostgreSQL 18 are handled; on PostgreSQL 18, making a column NOT NULL adds a NOT VALID not-null constraint and validates it in the no-transaction migration)

- [x] **Lock warnings** (`pgy diff` reports statements that lock or rewrite existing tables on stderr and in `--json`: non-concurrent index builds, foreign keys added validated to partitioned tables before PostgreSQL 18, primary key/unique/exclude constraints, `SET NOT NULL` without a validated `IS NOT NULL` check, rewriting type changes, `SET LOGGED/UNLOGGED`, and added columns with volatile defaults, stored generated expressions, identity or serial; `--no-warnings` to silence)
- [x] **Left-out unsafe changes** (without `--unsafe`, `pgy diff` warns about each statement it left out because it needs `--unsafe`: column type changes, dropped columns, constraint, index and domain check redefinitions, ...; kind `unsafe` for `--strict`)
- [x] **Strict mode for CI** (`--strict` / `PGY_STRICT=1`: `pgy diff`, `validate` and `pull` exit 1 on the finding kinds in `.pgy.yml` `ci.fail_on` (lock, public_revoke, dependents, unsafe, policy, validate, unsupported, all; default lock, public_revoke, policy, validate), and `pgy diff` refuses `--unsafe`/`--prune` while `ci.forbid_unsafe` (default true); warnings carry a `kind` in `--json`)
- [x] **Schema policy** (`.pgy.yml` `policy:` rules checked by `pgy validate` and `pgy diff`: `security_definer: hardened`, `require_grants`, `require_owners`, `row_level_security`, and `concurrent_indexes` in `pgy diff`; findings warn, and fail under `--strict`; `public_grants: by_kind | authoritative | explicit` sets which grants blocks cover PUBLIC; `lock_timeout` / `statement_timeout` are `pgy migrate`'s default timeouts)
- [x] **Reference Data** (`data: {key, rows}` on tables → INSERT missing rows, UPDATE changed columns, DELETE undeclared rows under `--unsafe --prune`; rows compared by PostgreSQL in the column types, including extension types and domains over them, with rows matched by the key types' equality (a `citext` key in another case is rewritten); foreign-key order; `pgy pull --data`)
- [x] **Renames** (`renamedFrom` on tables, columns, views, materialized views, sequences, types, domains, indexes, constraints, foreign keys, functions and procedures → `ALTER ... RENAME` / `SET SCHEMA`; enum `renamedLabels` → `RENAME VALUE`; applied only when the old name exists and the new one does not, emitted first so the rest of the plan and `--prune` see the renamed object)
- [x] **Pruning** (`diff --unsafe --prune` drops undeclared tables, views, materialized views, functions, procedures, sequences, domains and types in schemas the YAML uses, plus undeclared triggers, constraints and indexes on declared tables. Aggregates are pruned like functions. Extensions follow a present `extensions:` block (see Extensions). Extension members, partitions, primary keys, constraint-backed or inherited indexes/constraints/triggers, column-owned sequences, window functions, routines written in C or `internal` and `pgy.migrations` are never dropped. One `DROP` per object kind, so dependencies within a kind need no ordering)

## Level 4: Specialized Configurations
Advanced PostgreSQL-specific capabilities for niche use cases.

- [x] **Foreign Data Wrappers (FDW)** (top-level `servers:` → `CREATE SERVER` with wrapper/type/version/options, options diffed with `ALTER SERVER ... OPTIONS (ADD/SET/DROP)`, owner and comment, `renamedFrom` → `ALTER SERVER ... RENAME TO`, authoritative for `--prune`, which drops a server's user mappings with it and keeps a server that foreign tables still use; `foreign table <name>:` blocks → `CREATE FOREIGN TABLE ... SERVER ... OPTIONS`, columns diffed like tables plus per-column `options`, generated columns and `storage`, table options, grants, owner, comments, check constraints, triggers, renames, foreign partitions (`partitionOf` → `CREATE FOREIGN TABLE ... PARTITION OF`, with `concurrently` indexes on the parent built plainly since foreign partitions cannot be indexed), inheritance children (`inherits` → `CREATE FOREIGN TABLE ... INHERITS`), `DROP FOREIGN TABLE` under `--prune`; pulled, with the `options` block of every server and foreign table, so options added to them later are noticed. User mappings are out of scope: their options hold credentials. A changed wrapper or server, and a table that is a foreign table in the database or the reverse, are reported, not altered)
- [x] **Full Text Search Configurations** (`text search configuration` (copy or parser + managed token mappings → `ADD/ALTER/DROP MAPPING`) and `text search dictionary` (template, named with or without its schema when an extension provides it, + options, create-only) blocks; comments diffed, prunable. Custom parsers and templates are out of scope: they need C functions)
- [x] **Collations** (`collation <name>:` blocks → `CREATE COLLATION` with provider/locale/lcCollate/lcCtype/deterministic/rules or `from`; create-only, comments diffed, pruned with `--prune`)
- [x] **Rules** (`rules:` on tables and views → `CREATE OR REPLACE RULE`; event/instead/where compared against live, actions only re-emitted with `replace: true`; comments diffed, prunable)
- [x] **Event Triggers** (top-level `eventTriggers:` → `CREATE EVENT TRIGGER` with event/tags/function; changed definition drop+recreate, `enabled` → `ALTER EVENT TRIGGER ... ENABLE/DISABLE/ENABLE REPLICA/ALWAYS`, comments diffed; present block authoritative for `--prune`)
- [x] **Logical Replication — Publications** (top-level `publications:` with tables (column lists, row filters), schemas, `allTables`, `publish`, `viaPartitionRoot`, `generatedColumns` (PostgreSQL 18 `publish_generated_columns`), `owner`; membership → `ALTER PUBLICATION ... SET`, options → `SET (...)`, comments diffed; switching `allTables` and `--prune` drops need `--unsafe`. Subscriptions are out of scope: they carry connection strings with credentials)
- [x] **Tablespaces** (`tablespace:` on tables, partitions, materialized views, indexes and key/exclusion constraints → `TABLESPACE` / `USING INDEX TABLESPACE`; moves with `ALTER ... SET TABLESPACE` (lock warning) or `REINDEX CONCURRENTLY` for `concurrently` indexes; pulled; tablespaces themselves are created outside pgy)

## Test Coverage

`make test` runs the unit tests. With `PGY_TEST_DSN` set to a PostgreSQL database, it also runs the integration tests, which CI runs against PostgreSQL 15, 16, 17 and 18.

| Where | What it checks |
|-------|----------------|
| `internal/schema` | parsing of every YAML format and key; merging across files; dependency ordering; the JSON Schema accepts every key (`jsonschema_test.go`, `jsonschema_features_test.go`) |
| `internal/diff` | SQL generation for each feature: create, skip when present, alter, unsafe gating, prune; normalization of live definitions; renames; lock warnings; reference data |
| `internal/group` | split migrations: ordering, deferral of cross-file references, each statement emitted once |
| `internal/pull`, `internal/validate` | YAML generation from live definitions; validation rules; every complete YAML example in the docs passes `pgy validate` |
| `internal/integration` | against a real server: each feature is applied, a second diff must be empty, the database is pulled, the pulled YAML must diff clean, and a schema rebuilt from it must match the original YAML; realistic SQL schemas in `testdata/pull` are pulled and rebuilt into a second database, and with `PGY_TEST_PGDUMP` set (as in CI) `pg_dump --schema-only` of the rebuild must match the original |
| `internal/cli` | commands end to end: diff → commit → migrate → status across schema versions, no-transaction migrations, configuration |

*Adding a feature touches the YAML model and parser (`internal/schema`), introspection, the plan and the simulator (`internal/diff`), `pgy pull`, `pgy validate`, the JSON Schema (`schemas/pgy.schema.json`) and the docs, and ships with unit and integration tests.*
