# PostgreSQL Feature Support

This document tracks `pgy`'s support for various PostgreSQL features within its YAML schema definitions and diff engine. It serves both as a capability matrix and a roadmap for future development.

Features are grouped by relative complexity and impact on the diffing engine.

Supported servers: PostgreSQL 15, 16, 17, 18 and 19 (the integration suite runs against each in CI). Syntax specific to a newer release is emitted only when the YAML asks for it: `nullsNotDistinct` needs 15+ (the floor anyway), changing a generated expression in place needs 17+ (before, the column is dropped and added again), and `virtual` generated columns, `enforced: false` and temporal `without overlaps`/`period` keys need 18+.

## Level 1: Basic Schema & Tables
These are the foundational elements required for almost any relational database application.

- [x] **Schemas** (Custom namespaces; a `schema <name>:` block or `schemas:` entry creates its schema where it is missing, also when it holds only `grants`, `comment` or `owner` or nothing (`schema reports: {}`, as `pgy pull` writes an empty schema), after the extensions the plan creates when no object pgy creates is in it, never for `public`, system or external schemas, and without putting the schema in reach of `--prune`; schema-level names containing a dot declared in double quotes, `table "x.y":`, and pulled that way; schema names containing a dot are rejected by `pgy validate`, left out by `pgy pull` with a warning and never pruned)
- [x] **Tables** (Base tables)
- [x] **Columns** (Data types, nullability, defaults)
- [x] **Primary Keys** (column `primaryKey: true`, a column list, or a named block that renames a live key and takes `include`, `with` and a `comment`)
- [x] **Foreign Keys** (`onDelete`/`onUpdate`, `match`, `deferrable`/`initiallyDeferred`, `notValid`)
- [x] **Indexes** (`concurrently: true` → `CREATE INDEX CONCURRENTLY` in a no-transaction migration, or for partitioned tables `ON ONLY` + per-partition concurrent builds + `ATTACH PARTITION`; indexes left invalid by an interrupted build are completed or rebuilt; Including unique indexes, non-btree methods via `using:` — gist/gin/brin/hash/spgist and access methods from extensions such as bloom — partial indexes via `where:`, operator classes via `opclass:`/`opclasses:` with their parameters (`gist_trgm_ops(siglen=32)`), expression indexes, per-column `collations` (compared with the column's or expression's own collation, whatever type the access method stores), per-column sort order — `desc`, `nulls last` —, `include` covering columns, `nullsNotDistinct`, `with` storage parameters, `statisticsTargets` for expression columns (`ALTER INDEX ... ALTER COLUMN n SET STATISTICS`, changed in place) and `concurrently` (built in a separate no-transaction migration). Live definitions are compared in full, expressions and predicates through the server when they differ as text; a changed index is dropped and recreated under `--unsafe`. Names over 63 bytes are truncated the way PostgreSQL stores them)
- [x] **UNIQUE Constraints** (Table-level and column-level; `nullsNotDistinct`, `deferrable`/`initiallyDeferred`, and `include`/`with` for the constraint's index)
- [x] **CHECK Constraints** (`noInherit`, `notValid`)
- [x] **NOT NULL Constraints** (Via column `nullable` property; on PostgreSQL 18, `notNullName` names the constraint on create and when it is added, a constraint with another name is renamed with `ALTER TABLE ... RENAME CONSTRAINT`, and `pgy pull` writes names that are not the default `<table>_<column>_not_null`; ignored with a warning before 18)
- [x] **EXCLUDE Constraints** (`expression` after `EXCLUDE`, compared with live element by element: a missing `USING`, a named default operator class and `operator(pg_catalog.op)` match what PostgreSQL prints; index storage parameters from the expression's `WITH (...)` or the `with` key, applied at creation and changed in place)
- [x] **Column Alterations** (`ALTER COLUMN ... TYPE / SET DEFAULT / DROP DEFAULT / SET NOT NULL / DROP NOT NULL` for existing columns. Types compared normalized — `varchar(255)` matches live `character varying(255)`, `serial` matches its live `integer` + `nextval` form — and through the server where the text differs, so a type modifier in any spelling PostgreSQL reads matches the stored one (`numeric(10)` is `numeric(10,0)`, `varchar( 5 )` is `character varying(5)`, PostGIS `geography(Point)` is `geography(Point,4326)`), for columns, arrays, composite attributes and domain base types alike; defaults compared with live casts stripped (`'x'::text` matches `'x'`), and through the server when PostgreSQL stores another spelling (`'1 hour'` is `'01:00:00'::interval`). Type changes are gated behind `--unsafe` and support a column-level `using:` expression; around one, the column's default is dropped and set again, redefined or pruned indexes and constraints on the column are dropped first and created afterwards, foreign keys retyped on both sides are dropped and re-added, and generated columns in the way lose their expression, or are dropped and added again with the indexes, constraints and statistics on them and the views that use them, when the YAML declares all of that. A dropped column (`--unsafe`) goes after the generated columns, policies and publications that use it, and is kept with a warning while a view, trigger, rule, policy or generated column that stays still uses it. Guard rails: identity changes follow the identity rules (adding or dropping one needs `--unsafe`), `nextval` defaults are never dropped, primary-key columns never emit `DROP NOT NULL`)
- [x] **Constraint Alterations** (Changed definitions of existing FK/check/unique/exclude constraints emit `DROP CONSTRAINT` + `ADD CONSTRAINT`, gated behind `--unsafe`. Live definitions introspected via `pg_get_constraintdef()`; comparison is normalized — casts, parentheses, whitespace, identifier quoting, and `public.` qualifiers are ignored, so `CHECK ((email <> ''::text))` matches `email <> ''`, but a cast to another type on each side is a change and a cast on one side only is settled through the server. FK `onUpdate`/`match`/`deferrable`/`initiallyDeferred`/`notValid`/`enforced`, unique `nullsNotDistinct`/deferrable, check `noInherit`/`notValid`/`enforced`, and PG18 temporal `without overlaps`/`period` columns are modeled and compared; `IN`/`BETWEEN`/`LIKE` rewrites, `CAST(x AS type)` and `pg_catalog.` qualifiers are understood; string literals are compared as written, apart from a `public.` qualifier in one that names an object (`'public.seq'::regclass`); a check or exclusion constraint that still differs is compared through the server, so constants may be written in any form their type reads. Limitation: primary keys are not compared)
- [x] **Comments** (`COMMENT ON` schemas, tables, columns, indexes, foreign keys, check/unique/exclude constraints, triggers, policies, types, domains, sequences, collations, functions, procedures, views, roles, publications, event triggers; comments of dropped-and-recreated objects are re-applied; diffed against live, PostGraphile smart tags safe)

## Level 2: Advanced Types & Logic
Features that encapsulate business logic, complex data structures, or procedural code.

- [x] **ENUM Types** (Including `ALTER TYPE ... ADD VALUE` for new labels, order-preserving)
- [x] **Composite Types** (Attribute order preserved from YAML declaration; missing attributes added with `ALTER TYPE ... ADD ATTRIBUTE`, type changes/drops under `--unsafe`; attribute `collate` and `comment`)
- [x] **Range Types** (`type: range` with subtype/subtypeOpclass/collation/canonical/subtypeDiff/multirangeTypeName; create-only)
- [x] **Extensions** (`CREATE EXTENSION` with `schema`/`version`/`cascade` and `comment` (`comment: null` for none, pulled for an extension whose control-file comment was removed), created in requirement order from the server's catalog, `dependsOn: [extension <name>]` and the requirements between PostgreSQL's own extensions (also for an extension the server lacks); relocatable extensions moved with `ALTER EXTENSION ... SET SCHEMA`, with the objects that follow them left alone and routines declared with the new schema in their signature replaced or altered in place, and a warning naming the declarations that still use the extension's types or functions unqualified when it moves off the `search_path`; version changes emit `ALTER EXTENSION ... UPDATE TO`, in a `-- pgy:new-session` migration of their own that runs first, each update as the first statement of a new connection (TimescaleDB requires that), unless the update needs an extension the plan creates, views the plan drops for it, or an extension whose update stays in the main migration, so updates always run in requirement order; both run before anything that uses the extension; an update script may drop and recreate the extension's objects, so under `--unsafe` the declared views that use them, directly or through other views, are dropped before the update and recreated after it with their grants, comments, owners, triggers and rules, while materialized views, routines with a SQL-standard body and undeclared views stay and are reported, as are the views without `--unsafe`; `pgy diff` warns about extensions and versions the server cannot install or update to, a schema the control file of an extension it creates does not allow, and a non-relocatable extension declared in another schema than it is in, whose references in the declared schema are then planned as references to the schema it stays in; pulled with non-default versions and requirements; a present `extensions:` block is authoritative for `--unsafe --prune`: installed extensions it does not list are dropped with `DROP EXTENSION` (no `CASCADE`) after every other drop, when they live in a schema the YAML declares objects in; `plpgsql`, the extensions in `.pgy.yml` `prune.keep_extensions`, those a kept extension requires and those still used by objects the plan does not drop are kept, the last with a warning naming the dependents)
- [x] **Objects an extension owns** (a `function` or `procedure` without `body`, a `view` without `query`, a `type` without `type:`, a `table` without `columns`, an `aggregate` without `sfunc` and `stype`, a `text search dictionary` without `template` and a `sequence` without options manage an existing object and never create it, nor its schema, which some extensions create themselves (a sequence without options is still created when it doesn't exist; a schema block of its own creates the schema after the extension, where it is still missing): function attributes via `ALTER FUNCTION`, emitted ahead of the creates that may need them, procedure `security`/`set`, grants, owner and comments; routines matched by argument types; privileges compared with the extension's own (`pg_init_privs`), so its grants stay unless the block names the grantee, and without the owner's, the previous owner's included; applied in the migration that creates the extension, compared with what the extension creates, which `pgy diff` learns by creating the plan's extensions in a transaction it rolls back (a table such an extension creates is managed like an installed extension's table even when declared with columns); `diff --from-empty` drops the policies and triggers declared on an extension's tables if its script created them and creates them again, and warns about tables declared with columns and rows in a plan that creates extensions; missing objects are reported; a table an extension owns is never created, altered or pruned, even when declared with columns; a schema an extension's script creates gets its grants compared with `pg_init_privs`; the functions, procedures, aggregates, types, domains and text search dictionaries an extension installs in `pg_catalog` (plv8, plls, plcoffee, `plpgsql`'s handlers) are read and declared under `schema pg_catalog:` like members elsewhere; `pgy pull` writes the members whose privileges changed, as `pg_dump` does, tables with their row level security and policies)
- [x] **Functions** (PL/pgSQL, etc.; replace-on-change via body/attribute diff → `CREATE OR REPLACE`, which keeps the live value of each attribute the YAML leaves unmanaged; a changed return type, a removed argument default or renamed arguments → `DROP` and `CREATE` under `--unsafe`, which keeps those attributes too and restores the grants, comment and owner the YAML leaves unmanaged; string bodies created with `check_function_bodies` off, as `pg_dump` does, when the plan creates or replaces more than one routine or anything else, so they may use what the same migration creates later, and checked at `CREATE` when the plan changes only one routine; `set` clauses diffed against `proconfig` → `ALTER FUNCTION ... SET / RESET`, created in the order the YAML gives and pulled in catalog order, and pulled as `set: {}` for SECURITY DEFINER routines without settings; `parallel`, `cost` and `rows` diffed → `ALTER FUNCTION`; arg types may be schema-qualified — unqualified and `public.`-qualified are equivalent; argument type modifiers (`varchar(10)`), which PostgreSQL discards, are kept in the `CREATE` and ignored when routines are matched; overloads with the same name and different arguments are independent declarations)
- [x] **Triggers** (Including `UPDATE OF` columns, `enabled` state (`ENABLE/DISABLE [REPLICA|ALWAYS] TRIGGER`), transition tables via `referencing: {old, new}`, `WHEN (condition)` guards via `when:` and `CREATE CONSTRAINT TRIGGER` with `deferrable`/`initiallyDeferred`. Matched by definition via `pg_get_triggerdef()` — a changed trigger is dropped and recreated in the same migration; equivalent definitions (case, casts, parens, event order, `EXECUTE FUNCTION` vs `PROCEDURE`, a `pg_catalog.` qualifier, and every spelling of an argument: `moddatetime(updated_at)` is `moddatetime('updated_at')`) emit no SQL, and a `when:` condition PostgreSQL stores in another spelling is compared through the server. Trigger creates are emitted after all table and function creates, so trigger functions may `dependsOn` their own table. `dependsOn` cycles are a hard error in `pgy diff`)
- [x] **Views** (Standard `CREATE VIEW`; `INSTEAD OF` triggers via `triggers:`; declared queries compared with the live definition through a temporary view (`CREATE OR REPLACE`, or `DROP` and `CREATE` with dependent views under `--unsafe` when columns change), and as text, with one warning and never replaced, where the role lacks a privilege the temporary view needs (USAGE on a schema the query names); a view dropped and created again for its columns, a column type change or an extension update gets back its grants (column grants included), comments, column defaults, a materialized view's column settings, owner, options, triggers and rules, declared or not; `replace: true` forces `CREATE OR REPLACE` on every diff; `columnComments` → `COMMENT ON COLUMN`; `columnGrants` → column privileges on views and materialized views, diffed and pulled like table column grants; `securityInvoker`/`securityBarrier`/`checkOption` diffed against live reloptions → `ALTER VIEW ... SET/RESET`)
- [x] **Materialized Views** (a changed query recreates the view and its indexes under `--unsafe`; `withData: false`; `with` storage parameters → `ALTER MATERIALIZED VIEW ... SET/RESET (...)`; `indexes:` created and diffed like table indexes; `columns:` sets the compression, storage, statistics target and n_distinct of its columns → `ALTER MATERIALIZED VIEW ... ALTER COLUMN`)
- [x] **Domains** (`domain <name>:` blocks → `CREATE DOMAIN` with type/collate/default/notNull/check/constraintName and named `checks`, which `notValid: true` adds `NOT VALID` and removing it validates; default/not null diffed → `ALTER DOMAIN`, missing checks added, changed checks replaced and undeclared ones dropped under `--unsafe`; defaults and checks that differ as text are compared through the server; comments diffed)
- [x] **Aggregates** (`aggregate <name>(args):` blocks → `CREATE OR REPLACE AGGREGATE` with sfunc/stype/finalfunc/combinefunc/initcond/parallel, the moving-aggregate options, serialfunc/deserialfunc, finalfunc extra/modify, sspace and sortop, ordered-set (`order by` arguments) and hypothetical-set aggregates, created after their functions; diffed against `pg_aggregate`, comments, owners, grants and `revokePublic` (`GRANT ... ON FUNCTION`), prunable, pulled)
- [x] **Procedures** (`procedure <name>(args):` blocks → `CREATE PROCEDURE`; replace-on-change via body/security/`set` diff → `CREATE OR REPLACE`, or `DROP` and `CREATE` under `--unsafe` for a removed argument default or renamed arguments, both keeping the unmanaged `security`, `set`, grants, comment and owner; grants, `revokePublic`, comments)
- [x] **Procedural Languages & Transforms** (functions and procedures in any installed language, e.g. PL/Perl, PL/Python, PL/Tcl; `pgy pull` writes each body so the routine is recreated byte for byte, including the first-line indentation PL/Python needs; `body: ""` is an empty body; PL/Rust (`plrust`), which stores a JSON document with the compiled library in `prosrc`, is compared and pulled by the source in that document; a changed `language` → `CREATE OR REPLACE`; `transform: [types]` → `TRANSFORM FOR TYPE` for the transform extensions (`hstore_plpython3u`, `jsonb_plperl`, ...), diffed against `protrftypes`, pulled, and kept across `CREATE OR REPLACE` when left unmanaged. Languages and transforms themselves come from extensions; ones created by hand are reported by `pgy pull`. A top-level `languages:` block manages the privileges of the languages that exist, built in or from an extension: `GRANT` / `REVOKE USAGE ON LANGUAGE` right after the extension statements and before any routine, `PUBLIC`'s default left alone unless listed (`public: []` revokes it) or the language's extension revoked it (`pljava`'s `java`; likewise for the routines and types of an extension), compared with `pg_init_privs` for a language an extension owns, a language that an extension of the same plan may bring, under any name, granted in a `DO` block that skips it unless it exists and is trusted, a missing or untrusted language reported, and pulled for every language whose privileges changed, `sql` included)

## Level 3: Architecture & Security
Features necessary for scaling, multi-tenancy, and advanced security models.

- [x] **Table Inheritance** (`inherits: [parents]` → `CREATE TABLE ... INHERITS`, ordered after the parents; missing parents added with `ALTER TABLE ... INHERIT`, removed ones dropped with `NO INHERIT` under `--unsafe`; inherited columns left to the parent, with the child's own settings for them (default, NOT NULL, storage, statistics, comment) under typeless `columns:` entries; pulled)
- [x] **Typed Tables** (`of: schema.type` → `CREATE TABLE ... OF type`, after the type; existing tables linked with `ALTER TABLE ... OF`, unlinked with `NOT OF` under `--unsafe`; column options under typeless `columns:` entries; type attribute changes cascade to typed tables; pulled)
- [x] **Table Partitioning** (Parent `partitionBy: {type: range|list|hash, columns: [...]}`; children as separate tables with `partitionOf` + `forValues` (from/to, in, modulus/remainder) or `default: true` → `CREATE TABLE ... PARTITION OF`; children auto-ordered after parent; a declared partition that is an ordinary table is attached with `ATTACH PARTITION`; bounds are never altered and pgy never detaches; partitions' own column settings under typeless `columns:` entries; a partition's own index declared like its parent's is attached to the parent's index under its own name, or PostgreSQL's copy is renamed, and pulled when PostgreSQL would name it otherwise; a parent index on only some partitions is pulled and rebuilt as a complete one)
- [x] **Row Level Security (RLS)** (`rowLevelSecurity: true` / `false` + named `policies:` with as (permissive/restrictive)/for/to/using/withCheck; omitting the key leaves live RLS unmanaged, `false` emits `DISABLE ROW LEVEL SECURITY` gated behind `--unsafe`; policies matched by name with definitions diffed — a changed as/for/to/using/withCheck drops and recreates the policy; `using`/`withCheck` expressions that differ as text are compared through the server)
- [x] **Grants & Privileges** (`GRANT` / `REVOKE` on tables, views, materialized views, sequences, types, domains, functions, procedures, schemas, foreign servers, foreign-data wrappers, languages, and columns — column-level via `grants:` under a table column or `columnGrants:` on a view or materialized view; `PUBLIC` covered by grants blocks on objects with no `PUBLIC` default (tables, views, sequences, columns, servers, wrappers, schemas), and managed on routines, types, domains and languages when listed (`public: []`) or by `revokePublic`; an empty list (`role: []`) revokes everything for that role while keeping the object managed; `all` / `all privileges` expanded to the privileges of the object's kind on the server's version (`maintain` on tables from PostgreSQL 17) before comparing; all revokes ordered before all grants so narrowing a table grant to column grants is safe)
- [x] **Ownership** (`owner:` on schemas, tables, views, materialized views, sequences, functions, procedures, types, domains → `ALTER ... OWNER TO`, diffed against live; with a connection, the statements that need the privileges of the owner of an existing object the connecting role can't act for (`ALTER`, `COMMENT ON`, `CREATE OR REPLACE`, its indexes, policies, rules, statistics and partitions, the drops that recreate it, `ALTER DATABASE ... SET`, a `GRANT`/`REVOKE` without the grant option, a trigger without the `TRIGGER` privilege) are left out with everything the plan does for that object and for the objects that change with it, with one `not_owner` warning per object, also for an external role's, so the migration applies and no declared change disappears unnoticed)
- [x] **Default Privileges** (top-level `defaultPrivileges:` → `ALTER DEFAULT PRIVILEGES [FOR ROLE] [IN SCHEMA] GRANT/REVOKE` on tables/sequences/functions/types/schemas, and on large objects from PostgreSQL 18 (`largeObjects`, without `in:`), with grant option, per-grantee authoritative, emitted before creates)
- [x] **Database Settings** (top-level `database: {set: ...}` → `ALTER DATABASE <current> SET/RESET`, and `database: {roles: ...}` → `ALTER ROLE ... IN DATABASE <current> SET/RESET`, compared with `pg_db_role_setting`, pulled)
- [x] **Roles & Users** (Top-level `roles:` block → `CREATE ROLE` with login/superuser/createdb/createrole/replication/bypassRLS/noinherit/connection limit; `set` → `ALTER ROLE ... SET/RESET`; `inRoles` memberships via `GRANT role TO role`, with admin/inherit/set options (changed in each grant, `GRANTED BY` its grantor, on PostgreSQL 16+), undeclared memberships revoked under `--unsafe --prune` for roles that declare `inRoles`, except the connecting role's memberships in the roles it created on PostgreSQL 16+; `validUntil`; explicitly set attributes diffed against `pg_roles` → `ALTER ROLE`; with a connection as a role that is not a superuser, the `ALTER ROLE`, `COMMENT ON ROLE`, `GRANT` and `REVOKE` statements on existing roles it may not change (a superuser role; on PostgreSQL 16+ a role it holds no `ADMIN` option on, a grantor whose privileges it lacks, `CREATEDB`/`REPLICATION`/`BYPASSRLS` it doesn't have; on 15 without `CREATEROLE`, a replication role) are left out with one `not_owner` warning per role; never dropped, no passwords; `pgy pull --roles` leaves out only the bootstrap superuser, and writes the connecting role's memberships and settings without its attributes)
- [x] **Sequences** (`sequence <name>:` blocks → `CREATE SEQUENCE IF NOT EXISTS` with as/increment/minValue/maxValue/start/cache/cycle/ownedBy and `unlogged`; set options diffed against `pg_sequence` → `ALTER SEQUENCE`, `unlogged` → `SET LOGGED/UNLOGGED`; comments diffed; a block named like the sequence of a serial or identity column manages its grants and comment without creating it, and `pgy pull` writes one for each such sequence with grants or a comment)
- [x] **Table & Column Storage** (`unlogged` → `SET LOGGED/UNLOGGED` under `--unsafe`; `with` storage parameters → `SET/RESET (...)`, values other than numbers and lower-case words passed as string literals, in the order the YAML gives (pulled in catalog order), also for indexes, constraints and materialized views; column `collate` (changes under `--unsafe`), `compression`, `storage`, `statisticsTarget` and `nDistinct`/`nDistinctInherited` (attribute options) diffed against live, and applied to added columns in the same migration)
- [x] **Replica Identity** (`replicaIdentity: default|full|nothing|index <name>` → `ALTER TABLE ... REPLICA IDENTITY`, diffed against live)
- [x] **Clustering** (`clusterOn: <index>|none` → `ALTER TABLE ... CLUSTER ON` / `SET WITHOUT CLUSTER`, diffed against `indisclustered`)
- [x] **Extended Statistics** (`statistics:` → `CREATE STATISTICS` with kinds and column/expression lists, in the table's schema or the one `schema:` names, and identified by that schema and their name; drop+recreate on change, `statisticsTarget` → `ALTER STATISTICS ... SET STATISTICS`, comments, prunable)
- [x] **Generated Columns** (Column `generated: <expr>` → `GENERATED ALWAYS AS (expr) STORED`, or `VIRTUAL` with `virtual: true` on PG18+; live generation expressions introspected and compared normalized, and through the server when they still differ; under `--unsafe` a changed expression emits `SET EXPRESSION` (PG17+; on 15/16 the column is dropped and added again, with what is on it) and a removed one `DROP EXPRESSION`)
- [x] **NOT NULL NOT VALID** (PostgreSQL 18: a column with `notValid: true` keeps its not-null constraint `NOT VALID`; pulled from `convalidated = false` not-null constraints)
- [x] **Identity Columns** (Column `identity: always | byDefault`, or a map with sequence options (start/increment/minValue/maxValue/cache/cycle, and `sequenceName`, renamed in place) → `GENERATED ... AS IDENTITY (...)`; kind and options diffed → `SET GENERATED` / `SET <option>`; added to or dropped from existing columns under `--unsafe`; overrides `default`)

## Migration Workflow
How pgy plans, reviews and applies changes safely.

- [x] **Adopting a database** (`pgy pull` writes YAML that diffs clean against the source database and rebuilds it from scratch; `--data` includes table rows; `--schema` / `--exclude-schema` pull some schemas with only the extensions, publications and event triggers they need, and leave the database settings out unless `--database-settings` is given; configuration tables of the extensions it writes that hold rows `pg_dump` keeps and the YAML doesn't carry are reported, with their row count, as kind `unsupported`; `--json` with `--out` prints the files and warnings)
- [x] **External objects** (`.pgy.yml` `external:` block with glob patterns for `schemas`, `roles`, `settings` and `relations` a hosting platform or an extension owns: `pgy pull` leaves them out (external schemas with their objects, extensions, event triggers and publications, objects external roles own with their role entries and `for:` default privileges, external settings, external relations, with a warning about a view or materialized view that reads an external relation a rebuilt database lacks); `--prune` never drops anything in external schemas, external relations, or the event triggers, extensions, publications, servers and wrappers external roles own; external schemas are never created; tables in them are declared without columns to manage policies, triggers, grants, RLS, comment, owner and rows additively (unlisted ones are left alone); grants blocks leave external roles' privileges alone unless they name them; existing external roles are never altered or commented on; external settings are never reset; `pgy validate` doesn't report references to external objects; see [Hosted platforms](hosted-platforms.md), with lists for Supabase, RDS/Aurora, Neon, Cloud SQL and Azure)
- [x] **Expressions compared through the server** (a column default, generated expression, check or exclusion constraint, index expression or predicate, policy, trigger, view column default, domain default or check, or routine argument default that still differs from the live one as text is attached to a temporary copy of its table, or to a temporary domain or routine, in a transaction that is always rolled back, and read back as PostgreSQL stores it; so any spelling PostgreSQL accepts diffs clean — `'1 hour'::interval`, `'a=>1'::hstore`, `cube '(0,0,0)'`, `issn('1436-4522')` — with built-in and extension types alike. So is one that matches as text only because the text comparison dropped a cast from one side (an index on `(email::text)` against the `citext` column `email`) or a schema qualifier `pg_catalog` shares (`public.gen_random_uuid()` against core `gen_random_uuid()`, `operator(public.=)` against `OPERATOR(pg_catalog.=)`), and the server's answer can make it a change; a cast to another type on each side (`(emb::halfvec(3))` against `(emb::halfvec(4))`) is a change as text. Runs only when the text comparison leaves something to it, in one round trip, so YAML as `pgy pull` writes it costs nothing; needs the `TEMPORARY` privilege and a writable session, and otherwise warns once and compares as text; a table the role may not copy (no USAGE on its schema, no SELECT) has its definitions compared as text, named in one warning. Definitions that use something the same plan creates are compared as text in that diff. Declared column, composite attribute and domain types that differ from the live ones as text are resolved by the server in the same round trip (`to_regtype`/`to_regtypemod` on PostgreSQL 17+, a column of a temporary table before) and compared as `format_type` prints them. `pgy diff --strict-expressions` or `policy.strict_expressions: true` sends every definition to the server, also those that match as text, which catches regrouping parentheses at the cost of a copy of every table)
- [x] **Search-path independent comparison** (the database is read with `search_path` pinned to `public`, so `pgy diff` gives the same plan and `pgy pull` the same YAML through every connection, whatever the role, database or DSN sets; the schema of anything in `pg_catalog`, `public` or on the connection's `search_path` is optional in the YAML (`pg_catalog.int4` is `integer` in column, argument and transform types), `pgy pull` qualifies everything outside `public`, and a changed `database.set.search_path` is also set for the session that runs the migration)
- [x] **Offline validation** (`pgy validate`: JSON Schema, unknown columns, unresolvable dependencies, cycles, invalid combinations; `pgy diff` repeats its errors as warnings)
- [x] **Split migrations** (`diff --split` writes one migration per schema file or directory, ordered by dependencies, with cross-file references deferred to the group that can satisfy them)
- [x] **Transaction-free migrations** (`-- pgy:no-transaction`; `-- pgy:new-session` runs each statement first thing on a connection of its own, generated for extension updates; generated for `concurrently: true` indexes, including the `ON ONLY` + per-partition + `ATTACH` sequence on partitioned tables; interrupted builds are completed or rebuilt)
- [x] **Lock retries** (`migrate --lock-timeout D --retries N [--retry-wait D]` rolls back and retries a transactional migration that hit `lock_timeout` or a deadlock, with doubling waits up to 30s)
- [x] **Two-step constraint validation** (foreign keys and checks added to existing tables are added `NOT VALID` and validated in the no-transaction migration, retried by `pgy diff` until they succeed; `notValid: true` leaves them unvalidated, and dropping it emits `VALIDATE CONSTRAINT`; `validate: immediate` on a constraint, column or table adds them validated in one step instead, for tables that refuse `VALIDATE`, replacing a `NOT VALID` one; NOT VALID foreign keys on partitioned tables before PostgreSQL 18 are handled; on PostgreSQL 18, making a column NOT NULL adds a NOT VALID not-null constraint and validates it in the no-transaction migration)

- [x] **Lock warnings** (`pgy diff` reports statements that lock or rewrite existing tables on stderr and in `--json`: non-concurrent index builds, foreign keys added validated to partitioned tables before PostgreSQL 18, primary key/unique/exclude constraints, `SET NOT NULL` without a validated `IS NOT NULL` check, rewriting type changes, `SET LOGGED/UNLOGGED`, and added columns with volatile defaults (the volatility of the functions a default calls comes from the YAML that declares them, else from the catalog, which covers extension functions), stored generated expressions, identity or serial; `--no-warnings` to silence)
- [x] **Left-out unsafe changes** (without `--unsafe`, `pgy diff` warns about each statement it left out because it needs `--unsafe`: column type changes, dropped columns, constraint, index and domain check redefinitions, ...; kind `unsafe` for `--strict`)
- [x] **Strict mode for CI** (`--strict` / `PGY_STRICT=1`: `pgy diff`, `validate` and `pull` exit 1 on the finding kinds in `.pgy.yml` `ci.fail_on` (lock, public_revoke, dependents, not_owner, unsafe, policy, validate, unsupported, all; default lock, public_revoke, policy, validate), and `pgy diff` refuses `--unsafe`/`--prune` while `ci.forbid_unsafe` (default true); warnings carry a `kind` in `--json`)
- [x] **Schema policy** (`.pgy.yml` `policy:` rules checked by `pgy validate` and `pgy diff`: `security_definer: hardened`, `require_grants`, `require_owners` (neither checks declarations of objects an extension owns, and `require_owners` not the sequences of serial and identity columns; `pgy pull --owners` writes every owner of the kinds it lists), `row_level_security`, and `concurrent_indexes` in `pgy diff`; findings warn, and fail under `--strict`; `public_grants: by_kind | authoritative | explicit` sets which grants blocks cover PUBLIC; `lock_timeout` / `statement_timeout` are `pgy migrate`'s default timeouts)
- [x] **Reference Data** (`data: {key, rows}` on tables → INSERT missing rows, UPDATE changed columns, DELETE undeclared rows under `--unsafe --prune`; rows of an extension's configuration table matched against its `extcondition`, so only the rows `pg_dump` keeps are pruned or pulled, and written right after the extension, before the DDL that can make it fill the table itself; rows compared by PostgreSQL in the column types, including extension types and domains over them, with rows matched by the key types' equality (a `citext` key in another case is rewritten) whatever the `search_path`, and key columns of types without a btree operator class (`json`, `xml`, `point`, `box`, ...) rejected by `pgy validate` and `pgy diff`; foreign-key order; the sequences of serial, identity and `nextval` columns advanced past the rows, never backwards; `pgy pull --data`, with the positions of extension configuration sequences reported)
- [x] **Renames** (`renamedFrom` on tables, columns, views, materialized views, sequences, types, domains, indexes, constraints, foreign keys, functions and procedures → `ALTER ... RENAME` / `SET SCHEMA`; enum `renamedLabels` → `RENAME VALUE`; applied only when the old name exists and the new one does not, emitted first so the rest of the plan and `--prune` see the renamed object)
- [x] **Pruning** (`diff --unsafe --prune` drops undeclared tables, views, materialized views, functions, procedures, sequences, domains and types in schemas the YAML uses, plus undeclared triggers, constraints and indexes on declared tables. Aggregates are pruned like functions. Extensions follow a present `extensions:` block (see Extensions). A routine that objects the plan keeps still use (an event trigger the YAML doesn't manage, a default, a view) is kept with a `dependents` warning, and an object owned by a role whose privileges the connecting role lacks with a `not_owner` warning (an external role's without one), along with the triggers, constraints and indexes of a declared table such a role owns, so the migration applies. Extension members and the triggers, rules, constraints and indexes on an extension's tables and views or on declarations without columns or query, partitions, undeclared inheritance children of a kept table (reported in a warning), primary keys, constraint-backed or inherited indexes/constraints/triggers, column-owned sequences, window functions, routines written in C or `internal`, external objects (see External objects) and `pgy.migrations` are never dropped. One `DROP` per object kind, so dependencies within a kind need no ordering)

## Test Coverage

`make test` runs the unit tests. With `PGY_TEST_DSN` set to a PostgreSQL database, it also runs the integration tests, which CI runs against PostgreSQL 15, 16, 17, 18 and 19. The tests that need PL/Perl or PL/Python skip on a server that cannot load them. The `postgres:*-alpine` images ship these languages without the runtimes they link against, so CI installs the runtimes into its service containers (`apk add perl python3 tcl`, plus a `libperl.so` link in `/usr/lib`). It also sets `PGY_TEST_REQUIRE_PL`, which makes those tests fail instead of skip when a language does not load.

| Where | What it checks |
|-------|----------------|
| `internal/schema` | parsing of every YAML format and key; merging across files; dependency ordering; the JSON Schema accepts every key (`jsonschema_test.go`, `jsonschema_features_test.go`) |
| `internal/diff` | SQL generation for each feature: create, skip when present, alter, unsafe gating, prune; normalization of live definitions; renames; lock warnings; reference data |
| `internal/group` | split migrations: ordering, deferral of cross-file references, each statement emitted once |
| `internal/pull`, `internal/validate` | YAML generation from live definitions; validation rules; every complete YAML example in the docs passes `pgy validate` |
| `internal/integration` | against a real server: each feature is applied, a second diff must be empty, the database is pulled, the pulled YAML must diff clean, and a schema rebuilt from it must match the original YAML; realistic SQL schemas in `testdata/pull` are pulled and rebuilt into a second database, and with `PGY_TEST_PGDUMP` set (as in CI) `pg_dump --schema-only` of the rebuild must match the original |
| `internal/cli` | commands end to end: diff → commit → migrate → status across schema versions, no-transaction migrations, configuration |

*Adding a feature touches the YAML model and parser (`internal/schema`), introspection, the plan and the simulator (`internal/diff`), `pgy pull`, `pgy validate`, the JSON Schema (`schemas/pgy.schema.json`) and the docs, and ships with unit and integration tests.*
